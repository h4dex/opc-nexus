# OPC-Nexus 修复说明（2026-08-24）

本次提交面向 `v2.0.1` Hermes Quest 工作台，重点是把真实执行能力、工具桥接、数字员工建档和验收流程接通。所有执行结果仍以 OPC-Nexus Main/Orchestrator 的真实状态、产物 Manifest 和审计记录为准；没有恢复 DSH 调度器，也没有加入 Mock 或自动伪成功。

## 修复内容

### 1. Hermes Provider 与数字员工路由

- 验收脚本配置真实 Provider 后，会同步更新 `eng-nexus` 的显式 Provider、协议和模型覆盖，避免 Hermes 对话走新 Provider、数字员工任务却继续走旧中转站。
- Hermes 冷启动门禁从 45 秒调整为 120 秒。Dashboard/Gateway 启动期间继续显示 starting 状态，服务未健康前不会伪装为在线。
- Hermes 运行时继续使用固定版本和项目隔离的 `HERMES_HOME`，Provider 密钥只在 Main 进程通过 safeStorage/短期环境注入。

### 2. Hermes 创建数字员工与动态组队

- 新增受 Main 治理的 `nexus_create_employee`，只有老板明确要求并携带 `ownerConfirmed=true` 时才会创建真实员工。
- Main 校验员工名称、职责、记忆模式（长期/短期/无记忆）、权限、并发、能力和真实可用引擎，并记录审计。
- 项目默认不强制绑定员工；只有老板明确要求时才加入项目固定员工池，普通复杂任务由 Hermes 根据能力动态组队。

### 3. Hermes 工具桥接与共享能力

- Hermes 项目模式接入受项目目录、能力策略和审计约束的真实工具：网络搜索/聚合/调研、HTTP、浏览器、电脑控制、音频合成、FFmpeg 视频处理、图片生成。
- 新增 Office Skills 的幂等补齐和真实运行时依赖校验：`python-docx`、`openpyxl`、`python-pptx`。
- 图片生成只允许进入项目工作目录，要求老板确认，并返回真实文件大小和 SHA-256；Provider 不支持时返回明确错误，不生成占位图。
- Hermes 原生工具、MCP 和项目 Skill 仍通过 OPC-Nexus Main 的项目范围、权限和审计边界，不让 Renderer 或 Hermes 子进程直接改 SQLite。

### 4. 委派错误和失败跟进

- `nexus_delegate_task` 现在透传 HTTP 422 响应体中的治理原因，能显示具体的员工、权限、验证前置条件或项目限制，而不是只显示 `Unprocessable Entity`。
- 计划实现任务完成后，Main 会自动唤醒主秘书发起独立验收；验收员工必须独立、真实读取任务状态和产物，只有 `validationVerdict=PASS` 才能交付。
- **新增失败跟进**：实现任务进入 `FAILED`、`CANCELLED` 或 `INTERRUPTED` 时，Main 会写入一次持久化的主秘书跟进队列。Hermes 必须先调用 `nexus_task_status`，没有真实产出时再用 `nexus_delegate_task(intent=status_inquiry)` 询问原员工；只有在预算、权限和工作目录仍有效时才能提出一次有界重派，不能无限重试或把失败改成成功。
- 失败跟进、独立验收和验收结果读取均具备去重和重启恢复保护。

### 5. 小说/创作场景验收脚本

- 新增小说、影视/创作团队、图片生成和 Office Skills 的真实验收入口，均使用 Electron、preload、Hermes 项目代理和 Main 正式接口，不直接写数据库。
- 小说脚本真实创建员工、澄清、提交计划、批准、派工、读取 Manifest、执行独立验收并统计实际文件字数。
- 任务超时或脚本异常时通过正式 `cancelTask` 收尾，避免留下孤儿任务。
