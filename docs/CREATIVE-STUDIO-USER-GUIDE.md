# Hermes 创作团队操作说明

本说明以“老板通过 Hermes 组建小说或影视团队”为例，描述当前 OPC-Nexus 的真实使用方式。员工不是项目的固定组成部分；项目默认由 Hermes 动态选人，只有老板明确要求时才加入固定员工池。

## 先决条件

1. 在「引擎中心」配置并验证至少一个真实引擎（本轮使用 `eng-nexus`）。
2. 在「设置/模型供应商」配置 Provider、API Key，并使用“读取上游模型列表”选择模型。
3. 创建项目并选择真实工作目录。目录会作为所有员工的沙箱和交付根目录。
4. 打开「Quest」，确认右上角显示 Hermes 健康状态。服务停止或 Provider 不可用时不能继续派工。

## 用 Hermes 创建员工

在 Quest 对话中明确说明“老板要创建哪些员工”，同时给出职责和记忆策略。例如：

```text
老板要建立一个真实的小说创作团队，请创建以下数字员工：
1. 世界观架构师：长期记忆，维护世界规则和设定文档；
2. 角色设计师：长期记忆，维护角色卡；
3. 章节写手：短期记忆，只负责当前首章；
4. 独立文学验收编辑：无需记忆，只做单次验收。
每名员工填写具体 role、systemPrompt 和 agentsMd。不要加入固定项目池，项目保持动态组队。
创建完成后只返回 OPC-Nexus 返回的真实员工 ID，不要声称已经执行任务。
```

Hermes 会调用 `nexus_create_employee`。Main 会校验老板确认、名称、权限、并发、记忆策略和真实引擎，然后持久化员工并写审计。回复中的员工 ID 才能用于后续派工，不能手写或猜测 ID。

## 复杂任务流程

1. 老板描述目标、交付文件、工作目录限制和验收标准。
2. Hermes 先调用 `clarify`，老板回答持久化问题。
3. Hermes 提交计划草案；Quest 显示版本和 SHA-256 hash。
4. 老板点击批准并派工。只有 DSH/Cordis 治理层通过项目、员工、权限、预算和 DAG 校验后才创建真实任务。
5. Quest 任务面板显示每个员工的 `QUEUED/RUNNING/COMPLETED/FAILED` 和进度。交付文件由员工写入项目目录，Main 生成带 SHA-256 的 Delivery Manifest。
6. 实现任务全部完成后，由主秘书使用 `nexus_delegate_task` 把任务交给未参与实现的独立验收员工，`intent` 必须是 `validation`，并提供全部实现任务 ID。
7. 主秘书必须使用 `nexus_task_status` 读取权威 `PASS/FAIL/BLOCKED`。只有 `PASS` 才进入交付完成；`FAIL` 进入返工，`BLOCKED` 显示缺失条件。

## 记忆策略

- `long_term`：员工拥有项目范围内的 Hermes 文件记忆，适合世界观、产品规范等长期知识。
- `short_term`：只使用当前 Hermes 会话上下文，适合一次项目阶段。
- `none`：不读取历史执行结果，只返回本次调用结果，适合独立验收和一次性任务。

## 常见阻断

- `422 employee ...`：员工参数、引擎状态、权限或项目范围不合法；修正原因后重新描述，不要重复点击。
- `validation must be assigned to an independent employee`：验收员工参与了实现任务，必须改派未参与实现的员工。
- Hermes `503/502`：上游 Provider 暂时不可用，任务不得显示成功；等待 Provider 恢复后重试。
- 服务状态为 `stopped/error`：先重启当前项目 Hermes，确认健康后再发送或派工。

影视团队可以复用相同流程，把员工职责替换为故事开发、剧本、分镜/制片和独立导演验收，并把产物目录设为 `preproduction/`。
